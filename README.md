# Z Design

The central engineering design and architecture repository for the [Z Programming Language](https://github.com/zii-lang).

This repository contains technical designs, architectural documentation, engineering decisions, and proposals that guide the development of the Z ecosystem.

## Purpose

The purpose of this repository is to provide a shared place for documenting and discussing the technical direction of Z.

It aims to:

- Document the architecture and internal design of Z projects.
- Establish common engineering conventions and design principles.
- Document significant technical proposals and changes.
- Record important architectural and engineering decisions.
- Maintain documentation of relationships between components of the Z toolchain.

## Documentation

The documentation website is available at:

**[Z Design Documentation](https://zii-lang.github.io/design/)**

The repository is organized into the following areas:

| Directory | Description |
|---|---|
| `docs/architecture/` | Overall architecture of the Z ecosystem and its components. |
| `docs/projects/` | Technical designs for individual Z projects. |
| `docs/decisions/` | Architecture Decision Records (ADRs). |
| `docs/development/` | Engineering guidelines and development processes. |

## Projects

This repository documents the design of projects within the Z ecosystem, including:

- **[Zirsakht](https://github.com/zii-lang/zirsakht):** Shared infrastructure and core utilities.
- **[Zaban](https://github.com/zii-lang/zaban):** Syntax infrastructure, including lexing, parsing, and AST definitions.
- **[Zolal](https://github.com/zii-lang/zolal):** Toolchain and package management.
- **Z Compiler:** The compiler implementation and compilation pipeline.

## Contributing

Contributions to the design and architecture of Z are welcome.

You can contribute by:

- Improving existing design documentation.
- Proposing new architectural designs.
- Reviewing and discussing existing designs.
- Documenting important engineering decisions.

All contributions should be submitted through GitHub Pull Requests and are subject to review.
