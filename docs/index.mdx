# Z Design

Welcome to **Z Design**, the central engineering design and architecture documentation for the Z Programming Language.

This documentation describes the technical foundations, internal architecture, and engineering decisions behind the Z ecosystem.

Its purpose is to provide a shared understanding of how Z is designed, how its components interact, and how its architecture evolves.

## Scope

Z Design covers several aspects of the Z ecosystem:

### Architecture

Documents the overall architecture of Z, including the compiler, toolchain, shared infrastructure, and relationships between projects.

### Project Designs

Describes the internal design and responsibilities of individual Z projects, including their components, interfaces, and implementation considerations.

### Engineering Decisions

Records important technical decisions, their motivations, considered alternatives, and their consequences.

### Development Guidelines

Defines common engineering conventions and development practices used across the Z ecosystem.

## Projects

The Z ecosystem consists of multiple interconnected projects.

| Project | Description |
|---|---|
| [Zirsakht](https://github.com/zii-lang/zirsakht) | Shared infrastructure providing common facilities such as logging and source management. |
| [Zaban](https://github.com/zii-lang/zaban) | Syntax library providing lexing, parsing, and AST infrastructure. |
| [Zolal](https://github.com/zii-lang/zolal) | Toolchain management, dependency management, and manifest processing. |
| Z Compiler | The compiler responsible for translating Z programs into executable code. |

## Documentation Structure

- **Architecture:** High-level system architecture and component relationships.
- **Projects:** Technical designs for individual projects.
- **Decisions:** Records of architectural and engineering decisions.
- **Development:** Engineering guidelines and development processes.

## Contributing

Z Design is maintained collaboratively.

Contributions are welcome, including improvements to existing documentation, new technical designs, architectural discussions, and documentation of engineering decisions.

All contributions should be submitted through GitHub Pull Requests and are subject to review.

## Philosophy

The design documentation should remain a reliable reference for the engineering direction of Z.

Designs should explain not only what a system is intended to do, but also why it is designed that way, what alternatives were considered, and how its components fit into the larger ecosystem.
